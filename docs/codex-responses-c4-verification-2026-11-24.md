Status: implementation and focused local synthetic verification; full regression gates and independent acceptance are owned by the orchestrator. No real account files, SQLite stores, login, refresh, deployment or provider calls were used.

## Supported source contract and evidence

The preferred owner is native Codex using its documented file-backed credential option, `cli_auth_credentials_store = "file"`, under `$CODEX_HOME/auth.json`. The gateway accepts operator-selected `--auth-path`; it does not change Codex settings. Native `auth_mode:"chatgpt"` and historical omitted mode, `tokens.access_token` and optional `tokens.account_id` follow the pinned Codex shapes. Other native owner fields are tolerated without consuming refresh/id tokens.

Orchestrator-reviewed documents describe SQLite/legacy migration and private ephemeral app-server handoff. These inspected documents do not establish an external gateway file handoff; this is a bounded evidence statement, not a claim about every OpenClaw integration.

Legacy compatibility is explicit `type:"oauth"`, `provider:"openai-codex"`, `access`, `accountId`, optional `expires` milliseconds. A supplied `lastGood["openai-codex"]` must resolve to a fully valid matching profile. Without it exactly one matching profile is required. Invalid selected profiles never fall back. Modern `provider:"openai"`, SIWC, API-only and foreign profiles are rejected, because labels alone do not establish the credential flow. No fabricated provenance flag is used.

JWT payload decoding checks account consistency and known expiry seconds only. It verifies no signature, account access or route ownership. Explicit account and claim must agree; absent, empty and invalid IDs fail startup. Opaque access tokens require an explicit account and have unknown expiry. Owner login refresh remains external. Stop/restart through the existing process manager rebinds the configured file; an already running process keeps its initial snapshot. A Responses 401/403 uses a safe status/message: inspect the owner login/account, update via Codex and restart.

## Pre-final repair round — 2026-11-24

The initial full Rust gate exposed an outdated generic-message assertion in `rejects_file_without_usable_credentials`. It now requires the exact safe `Codex auth: access token required` reason; rejection and redaction remain enforced.

Material source probes supplied by the orchestrator showed legacy SIWC flows accepted under `oauth/openai-codex` labels, mode-less alternative native credentials incorrectly inferred as ChatGPT, and valid native null mode/one-dot opaque tokens rejected. The smallest repair excludes exact `authFlow` values `chatgpt-token-sharing` and `chatgpt-identity` during legacy selection and validation, so an incompatible explicit lastGood cannot fall back. Native null mode now follows absent mode: nonnull `OPENAI_API_KEY`, `personal_access_token`, `bedrock_api_key` or `bedrock_access_keys` blocks implicit ChatGPT inference, while explicit `chatgpt` retains owner precedence. Three-part tokens retain JWT claim/expiry checks; one-dot opaque tokens with explicit accounts remain compatible.

Source evidence supplied by the orchestrator for these findings: [pinned OpenClaw SIWC flows](https://github.com/openclaw/openclaw/blob/59b0aec099f5751ab221d724e339402eb111e828/extensions/codex/src/app-server/responses-oauth.ts#L18-L54), [native optional auth mode/storage](https://github.com/openai/codex/blob/8b096dce07b94aa4428ca310b871e5a873c8d2a2/codex-rs/login/src/auth/storage.rs#L51-L76), [native mode inference precedence](https://github.com/openai/codex/blob/8b096dce07b94aa4428ca310b871e5a873c8d2a2/codex-rs/login/src/auth/manager.rs#L1948-L1965).
